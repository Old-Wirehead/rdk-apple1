# Клавиатура, дисплей и Woz Monitor

<p class="lead">У Apple-1 всего четыре регистра ввода-вывода в PIA 6820 (или 6821) и монитор размером 256 байт. Это немного, но достаточно: в этой главе показано, как прочитать клавишу, вывести символ и использовать подпрограммы Стива Возняка.</p>

## Четыре регистра PIA

| Адрес | Имя | Чтение | Запись |
|---|---|---|---|
| `$D010` | `KBD` | код клавиши с установленным битом 7; чтение **подтверждает** клавишу | — |
| `$D011` | `KBDCR` | бит 7 = 1: клавиша ждёт | настройка (делает монитор) |
| `$D012` | `DSP` | бит 7 = 1: дисплей занят | выводимый символ (7 бит) |
| `$D013` | `DSPCR` | — | настройка (делает монитор) |

## Чтение клавиши

Дождитесь, пока бит 7 `KBDCR` станет 1, затем прочитайте `KBD`:

```asm
read:   lda KBDCR       ; a key?
        bpl read        ; bit 7 = 0: not yet
        lda KBD         ; ASCII code + $80
```

Клавиатура выдаёт только заглавные буквы (эмулятор преобразует строчные), с установленным битом 7: `A` даёт `$C1`, RETURN — `$8D`, ESC — `$9B`. Чтобы узнать, нажата ли клавиша, **не дожидаясь**, проверяйте только `KBDCR`:

```asm
        lda KBDCR
        bpl nokey       ; no key: carry on working
        lda KBD         ; a key: read it (and acknowledge it)
```

`jeu.s` (глава 23) использует это, чтобы выбрать случайное число: он считает в цикле, пока игрок не нажмёт клавишу.

## Вывод символа

Терминал Apple-1 принимает по одному символу и только когда готов: бит 7 `DSP` остаётся равным 1, пока предыдущий символ не выведен. Подпрограмма монитора `ECHO` ждёт за вас. Вот её четыре инструкции, прочитанные в мониторе эмулятора:

```mon
\
» FFEF.FFFFR

FFEF: 2C
FFF0: 12 D0 30 FB 8D 12 D0 60
FFF8: 00 00 00 0F 00 FF 00 00
```

Это `BIT DSP` / `BMI ECHO` / `STA DSP` / `RTS`. `ECHO` сохраняет A, X и Y. Поскольку оригинальный терминал выводит только **один символ за кадр**, около 60 в секунду, программу, которая много выводит, ограничивает дисплей, а не процессор; эмулятор по умолчанию соблюдает это ограничение (<kbd>F4</kbd> снимает его, глава 2).

Что дисплей делает с каждым кодом:

- **RETURN** (`$8D` или `$0D`) начинает новую строку; внизу экрана всё прокручивается на строку вверх.
- **Остальные управляющие символы** (`$00-$1F`, с битом 7 или без) игнорируются: ни очистки, ни возврата на символ, ни звонка.
- **Строчные** `$60-$7F` выводятся как заглавные `$40-$5F`: терминал сохраняет только 6 бит.
- После 40-го столбца курсор сам переходит на следующую строку.
- Кода для очистки экрана нет: это кнопка на машине (**🆑 Очистить экран**, <kbd>Ctrl</kbd>+<kbd>L</kbd>).

## Подпрограммы Woz Monitor

| Адрес | Имя | Вход | Действие | Регистры |
|---|---|---|---|---|
| `$FFEF` | `ECHO` | A = символ | выводит его | A, X, Y сохраняются |
| `$FFDC` | `PRBYTE` | A = байт | выводит его двумя шестнадцатеричными цифрами | A портится; X, Y сохраняются |
| `$FFE5` | `PRHEX` | A (младшая тетрада) | выводит одну шестнадцатеричную цифру | A портится; X, Y сохраняются |
| `$FF1F` | `GETLINE` | — | возврат в монитор: новая строка, затем ожидание команды | — |
| `$FF1A` | `ESCAPE` | — | как `GETLINE`, но сначала выводит `\` | — |
| `$FF00` | `RESET` | — | инициализирует PIA и монитор | — |

{{!ECHO}}{{!PRBYTE}}{{!PRHEX}}{{!GETLINE}}

Монитор использует нулевую страницу `$24-$2B` и буфер строки `$0200-$027F`; всё остальное — ваше (если только не нужно сохранить Integer BASIC, глава 16). Его команды (`300R`, `0300.031F`, `300: A9 8D`…) сведены в приложении B.

## Запуск и завершение программы

Программу запускает команда монитора `R` (`300R`), которая делает `JMP` по адресу, а не `JSR`. Поэтому в стеке **нет адреса возврата**: завершайте программу через `jmp GETLINE` (`$FF1F`), а не через `RTS`.

!!! attention "RTS и BRK не возвращают управление"
    `RTS` в конце программы, запущенной через `R`, снимает со стека что попало. `BRK` переходит по вектору прерывания ПЗУ, который равен `$0000` (последние три слова монитора выше: NMI `$0F00`, RESET `$FF00`, IRQ/BRK `$0000`): тогда процессор выполняет нулевую страницу. В обоих случаях нажмите RESET (<kbd>Ctrl</kbd>+<kbd>R</kbd>).

Зато программа, вызванная из BASIC через `CALL 768`, вызывается командой `JSR`: она должна заканчиваться `RTS`, чтобы вернуться в BASIC. В главе 16 показано, как разместить машинный код ниже программы на BASIC.

```mon
>» POKE 768,96
>» CALL 768
>
```

(`96` = `$60`, код операции `RTS`: самая маленькая возможная подпрограмма.)
