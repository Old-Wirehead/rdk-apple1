# Переменные, строки, массивы и память

## Числа

Integer BASIC знает только **16-битные целые со знаком**, от −32767 до 32767. Вычисление, выходящее за этот диапазон, останавливается с `*** >32767 ERR` (`200*200`, `32767+1`, а также `10/0` и `RND(0)`). Значение −32768 использовать нельзя (глава 18, ошибка 5). Нет ни десятичной точки, ни `INT`: `7/2` равно 3.

## Имена переменных

Это ограничение удивляет больше всего: имя переменной — это **одна буква, за которой может следовать одна цифра**.

| Имя | Результат (проверено) |
|---|---|
| `A`, `Z`, `B1`, `Z9` | принимается |
| `AB`, `CNT`, `SCORE`, `COUNTER` | `SYNTAX ERR` |
| `A12` | `SYNTAX ERR` |
| `A$`, `N$` | строка: только **одна буква** |
| `B9$`, `Z9$` | `SYNTAX ERR` |

Это даёт 26 × 11 = 286 возможных целочисленных переменных и 26 строк. Возьмите за привычку записывать назначение каждой переменной в `REM`.

## Строки

Строку нужно **объявить** до использования, указав её наибольшую длину (от 1 до 255): `DIM N$(20)`. `DIM B$(256)` даёт `>255 ERR`.

| Операция | Запись | Пример (N$ = "KAYAK") |
|---|---|---|
| длина | `LEN(N$)` | 5 |
| подстрока | `N$(i,j)`: символы с i по j | `N$(1,3)` = "KAY" |
| хвост | `N$(i)`: с символа i до конца | `N$(4)` = "AK" |
| сцепление | `A$(LEN(A$)+1)=B$` | "APPLE" + "-1" → "APPLE-1" |
| сравнение | только `=` и `#` | `IF N$="WOZ" THEN …` |

Присваивание строки длиннее её `DIM` даёт `*** STR OVFL ERR`, как и слишком длинный ответ на `INPUT`. Нет ни `MID$`, ни `LEFT$`, ни `CHR$`, ни `STR$`, ни `VAL`, ни `ASC` (последний есть в таблице, но не работает).

!!! astuce "Замена CHR$ и VAL"
    Чтобы вывести символ по его коду, держите строку-образец и вырезайте из неё: `DIM C$(26):C$="ABCDEFGHIJKLMNOPQRSTUVWXYZ"`, затем `PRINT C$(K,K)`. Чтобы прочитать число, используйте `INPUT N`, а не `INPUT N$`.

## Массивы

`DIM T(10)` создаёт массив из 10 целых, **пронумерованных от 1 до 10**. `T(0)` и `T(11)` дают `*** RANGE ERR`. Измерение только одно: для сетки 8 × 8 используйте `G((L-1)*8+C)`. В эмуляторе после `DIM` элементы равны 0; на настоящей машине память не обязательно очищена: инициализируйте массивы. Массив, слишком большой для памяти, даёт `*** MEM FULL ERR` (`DIM A(3000)` в 8 КБ).

## Память BASIC

![Память Apple-1: BASIC в $E000, программа ниже HIMEM, переменные выше LOMEM.](diagrams/ru/memoire.svg "diagram large")

BASIC хранит **программу вверху** памяти, растущей вниз от HIMEM, а **переменные внизу**, растущими вверх от LOMEM. Свободное место — между ними.

| Указатель | Адрес | Значение в 8 КБ | Роль |
|---|---|---|---|
| LOMEM | `$4A-$4B` (74-75) | `$0800` (2048) | начало переменных |
| HIMEM | `$4C-$4D` (76-77) | `$1000` (4096) | конец памяти BASIC |
| PP | `$CA-$CB` (202-203) | опускается вместе с программой | начало программы |
| PV | `$CC-$CD` (204-205) | поднимается вместе с переменными | конец переменных |

{{!LOMEM}}{{!HIMEM}}{{!PP (указатель программы)}}

`PRINT PEEK(202)+PEEK(203)*256` даёт начало программы, а `PRINT PEEK(204)+PEEK(205)*256` — конец переменных: свободное место — разность между ними. Целочисленная переменная вроде `A` занимает 6 байт.

!!! apple1 "Почему кассета BASIC начинается с $004A"
    Эти указатели находятся в нулевой странице, с `$4A` по `$FF`. Поэтому кассета BASIC записывает **два диапазона**: `004A.00FF` (указатели), затем программу от PP до HIMEM, например `0F2C.0FFF`. Команда `apple1-emu basic` вычисляет их за вас (её вывод — на французском: «10 строк, 212 байт… 1836 байт свободно для переменных… диапазоны ACI (после C100R)… затем E2B3R и RUN»):

    ```text
    10 lignes, 212 octets ; LOMEM $0800 HIMEM $1000 PP $0F2C ; 1836 octets libres pour les variables ; RAM 8 Ko
    Plages ACI (après C100R) : 004A.00FFR 0F2C.0FFFR   puis E2B3R et RUN
    ```

### Изменение LOMEM и HIMEM

Синтаксис — `LOMEM=n` и `HIMEM=n` (со знаком `=`, **а не** `:`, как на Apple II, что даёт `SYNTAX ERR`).

- `LOMEM=2304` сдвигает начало переменных и **очищает переменные** (программа остаётся). Полезно, чтобы зарезервировать `$0800-$08FF` под программу на машинном языке.
- `HIMEM=` **выше** (при большем ОЗУ, например `HIMEM=8192` в 16 КБ) работает и сохраняет программу.
- `HIMEM=` **ниже** **молча игнорируется** оригиналом, даже после `SCR` (глава 18, ошибка 11). **RDK G2 Basic его принимает**: программа в памяти сдвигается вниз вместе с границей, или выдаётся `MEM FULL ERR`, если она уже не помещается над переменными (`RANGE ERR` для отрицательного значения; `LOMEM=` даёт `RANGE ERR`, если оно не ниже начала программы, и `>32767 ERR` выше 32767). С оригиналом есть проверенный обход: записать указатель напрямую, затем `SCR`:

```basic title="Понижение HIMEM до 3072 ($0C00)"
POKE 76,0 : POKE 77,12 : SCR
```

При запуске G2 Basic HIMEM — это верх найденного ОЗУ, а LOMEM равен `$0800` (`$2000` с драйвером GEN2). (`76`/`77` = `$4C`/`$4D`, 12 × 256 = 3072.) Наберите эти три оператора в нумерованной строке или по отдельности в прямом режиме, **до** ввода программы: `SCR` её стирает.

## Смешивание BASIC и машинного языка

| Область (8 КБ) | Годится для кода 6502? |
|---|---|
| `$0000-$00FF` | нулевая страница: Woz Monitor использует `$24-$2B`, BASIC — как минимум `$4A-$FF`; избегайте её или сохраняйте и восстанавливайте |
| `$0100-$01FF` | стек 6502: нет |
| `$0200-$027F` | буфер строки Woz Monitor; перезаписывается каждой набранной строкой |
| `$0280-$07FF` | свободна, пока BASIC её не трогает: лучшее место |
| `$0800-…` | переменные BASIC (если LOMEM не поднят) |
| `… -$0FFF` | программа на BASIC |

Программа на машинном языке загружается с кассеты или через POKE и вызывается через `CALL 768` (для `$0300`). Она должна заканчиваться `RTS` и сохранять нулевую страницу BASIC. Минимальный пример:

```mon
>» POKE 768,96
>» CALL 768
>
```

(96 = `$60` = `RTS`: вызов сразу возвращается.)
