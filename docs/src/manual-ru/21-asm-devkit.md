# Ассемблер devkit

<p class="lead">Эмулятор содержит полноценный двухпроходный ассемблер 6502, совместимый с ca65. Он используется в редакторе, который ассемблирует при каждом нажатии клавиши, в командной строке и для проектов GitHub. Устанавливать ничего не нужно.</p>

## Рабочий цикл

![Рабочий цикл на ассемблере: написать, ассемблировать, запустить, отладить, затем экспортировать на настоящий Apple-1.](diagrams/ru/workflow-asm.svg "diagram large")

<ol class="steps">
<li><strong>Написать</strong>: <strong>📝 Редактор</strong>, затем <strong>Новый</strong> или <strong>Открыть</strong> файл <code>.s</code>, <code>.asm</code> или <code>.a65</code>. Подсветка синтаксиса различает инструкции, директивы, метки, числа и комментарии.</li>
<li><strong>Ассемблировать</strong>: делать ничего не нужно, ассемблирование следует за каждым изменением. Внизу панели показаны размер, адреса и строка для настоящей машины; ошибки показаны со строкой и столбцом.</li>
<li><strong>Запустить</strong>: <strong>▶ Запустить</strong> помещает байты в память по адресу <code>.org</code> и набирает команду Woz Monitor (<code>300R</code>).</li>
<li><strong>Отладить</strong>: <strong>⏺ Точка останова</strong> на строке с курсором, затем пошаговое выполнение в отладчике (глава 8), с вашими метками в дизассемблере.</li>
<li><strong>Экспортировать</strong>: <strong>📼 Экспорт WAV</strong> записывает кассету; на настоящем Apple-1 наберите <code>C100R</code>, показанный диапазон (<code>0300.0320R</code>), затем <code>300R</code>.</li>
</ol>

## Листинг и символы

**📃 Листинг** показывает для каждой строки адрес, полученные байты и исходный текст; строки, порождённые макросом, помечены `+`, включаемые файлы развёрнуты, а за ними следует таблица символов. Щелчок по строке возвращает к исходнику; щелчок на полях ставит точку останова. Вот листинг `hello.s` (глава 23), полученный из командной строки:

```text title="hello.lst"
0300  A2 00       start:  ldx #0
0302  BD 10 03    @next:  lda message,x   ; next character
0305  F0 06               beq @done       ; 0 = end of the string
0307  20 EF FF            jsr ECHO
030A  E8                  inx
030B  D0 F5               bne @next
030D  4C 1F FF    @done:  jmp GETLINE

                  message:
0310  8D                  .byte CR
0311  48 45 4C 4C         .asciiz "HELLO, APPLE-1!"
0315  4F 2C 20 41
…
; ---- Symboles (13)
; ECHO        $FFEF
; GETLINE     $FF1F
; message     $0310
; start       $0300
; start@done  $030D
; start@next  $0302
```

Локальные метки `@next` и `@done` принадлежат `start`: таблица называет их `start@next` и `start@done`, и отладчик принимает эти имена как адреса точек останова. (Листинг, записанный командной строкой, сохраняет французский заголовок *Symboles*.)

## Командная строка

{{asm (командная строка)|`apple1-emu asm`}} делает то же без окна:

```sh
apple1-emu asm hello.s                    # только проверка
apple1-emu asm hello.s -l hello.lst       # с листингом
apple1-emu asm hello.s -o hello.wav       # кассета (.wav или .aif)
apple1-emu asm hello.s -o hello.bin       # сырой двоичный файл
apple1-emu asm hello.s -o hello.hex       # дамп Woz для вставки в монитор
apple1-emu asm jeu.s -I ../common         # другая папка для .include
```

Каждая команда подытоживает ассемблирование и даёт строку для настоящего Apple-1. Итог выводится по-французски («33 байта … файлов: 2, символов: 13 / Кассета (после C100R): 0300.0320R, затем 300R / записано: hello.wav»):

```text
33 octets, $0300-$0320 ; 2 fichier(s), 13 symboles
Cassette (après C100R) : 0300.0320R   puis 300R
écrit : hello.wav
```

Без `.org` программа размещается с `$0300`. Дамп `.hex` имеет вид, который Woz Monitor принимает с клавиатуры, и заканчивается командой запуска:

```text title="t1.hex (фрагмент)"
0280: 34 12 34 12 10 05 FF 34
0288: 12 FF FF A8 02 EA EA EA
…
0280R
```

## Синтаксис

Строка содержит, в таком порядке и всё необязательно: метку, инструкцию или директиву и комментарий после `;`. Мнемоники и директивы можно писать строчными или заглавными буквами; символы чувствительны к регистру.

```asm
PTR     = $06           ; a constant (no byte produced)
start:  lda #0          ; a global label, followed by a colon
@loop:  inx             ; a local label: visible up to the next global one
        bne @loop
:       dex             ; an anonymous label
        bne :-          ; :- the previous one, :+ the next one, :-- the one before
```

{{!локальные метки}}{{!анонимные метки}}

**Числа**: `255` в десятичной системе, `$FF` в шестнадцатеричной, `%1010` в двоичной, `'A'` — символ ($41). Клавиатура возвращает коды с **установленным битом 7**: чтобы сравнить клавишу, пишите `'A' | $80`; `apple1.inc` так же определяет `CR = $8D`. `*` обозначает текущий адрес.

**Операции**, от низшего приоритета к высшему:

| Приоритет | Операции | Значение |
|---|---|---|
| 1 | <code>&#124;&#124;</code> | логическое ИЛИ (результат 0 или 1) |
| 2 | `&&` | логическое И |
| 3 | `=` `<>` `<` `>` `<=` `>=` | сравнения (0 или 1) |
| 4 | `+` `-` <code>&#124;</code> | сложение, вычитание, побитовое ИЛИ |
| 5 | `*` `/` `&` `^` `<<` `>>` | умножение, деление, И, исключающее ИЛИ, сдвиги |
| 6 (унарные) | `<` `>` `-` `~` `!` | младший байт, старший байт, смена знака, дополнение, логическое НЕ |

Так, `lda #<message` загружает младший байт адреса, а `lda #>message` — старший; `#>S+1` — это `(>S)+1`. Операции взятия остатка нет (`%` и `.mod` дают синтаксическую ошибку).

**Нулевая страница или абсолютный адрес.** Адрес ниже `$100`, известный во время ассемблирования, кодируется как нулевая страница (`lda $0006` даёт `A5 06`, как в ca65). Чтобы принудительно получить абсолютную форму, пишите `a:` (`lda a:$06` даёт `AD 06 00`); чтобы принудительно получить нулевую страницу — `z:`.

!!! attention "Определяйте константы нулевой страницы до их использования"
    Если `PTR = $06` записано **после** `lda PTR`, ассемблер ещё не знает значения и кодирует адрес двумя байтами. Он отмечает это жёлтым: `предупреждение: адрес нулевой страницы закодирован 2 байтами (символ определён ниже; определите его раньше или напишите z: или a:)`. Программа работает, но она длиннее, а режимы `(zp),Y` становятся невозможными.

## Директивы

| Директива | Действие | Пример |
|---|---|---|
| `.org адр` | адрес ассемблирования (и загрузки) | `.org $0300` |
| `.byte` (`.byt`) | байты, включая строки | `.byte CR, "OK", 0` |
| `.word` (`.addr`) | 16-битные слова, младший байт первым | `.word 10000, end` |
| `.asciiz` | строка с нулём на конце | `.asciiz "HELLO"` |
| `.res n[, знач]` | резервирует n байт (0 или знач) | `.res 3, $EA` |
| `.include "f"` | вставляет файл | `.include "apple1.inc"` |
| `.macro имя арг` … `.endmacro` | определяет макрос (`.mac`, `.endmac`) | см. `macros.s` |
| `.local a, b` | метки, свои для каждого вызова макроса | |
| `.repeat n[, перем]` … `.endrep` | повторяет блок, перем = 0 … n−1 | `.repeat 16, I` |
| `.if` `.elseif` `.else` `.endif` | условное ассемблирование | `.if WIDTH > 30` |
| `.ifdef` `.ifndef` | в зависимости от того, существует ли символ | `.ifdef APPLE1` |
| `.ifblank` `.ifnblank` | аргумент макроса пуст или нет | |
| `.defined(симв)` | 1, если символ существует (в выражении) | `.if .defined(d)` |
| `.define имя значение` | текстовая подстановка (`.undefine`) | `.define CHARACTER '*'` |
| `.setcpu "65C02"` | принимает инструкции 65C02 (`.pc02`, `.p02`) | |
| `.segment` `.code` `.data` `.rodata` `.bss` | принимаются для совместимости | |
| `.feature string_escapes` | `\n`, `\"`… в строках | |

{{!.org}}{{!.byte}}{{!.word}}{{!.asciiz}}{{!.res}}{{!.include}}{{!.macro}}{{!.repeat}}{{!.if}}{{!.setcpu}}

!!! attention "Сегменты ничего не перемещают"
    В ca65 и ld65 `.code`, `.data` и `.bss` направляют код в области, заданные конфигурацией компоновщика. Встроенный ассемблер создаёт **один блок** в порядке исходника: директивы сегментов принимаются, но не действуют, а `.bss` даёт нули. Для проекта, которому нужен настоящий файл `.cfg`, библиотека использует ca65 и ld65 (глава 4).

## Макросы, .repeat и условное ассемблирование

Макрос — это шаблон строк, копируемый при каждом вызове со своими аргументами. `.local` даёт каждому вызову собственные метки без конфликтов. `.repeat` разворачивает блок во время ассемблирования, что удобно и для **вычисления таблиц**:

```asm
squares:
.repeat 16, I
        .byte I * I     ; 0, 1, 4, 9 … 225
.endrep
```

Глава 23 представляет `macros.s`, где используется всё это, и `gen2-lores.s`, который вычисляет адреса 24 строк экрана с помощью `.repeat`.

## Сообщения об ошибках

Каждая ошибка указывает файл, строку, столбец и проблемный текст; пока остаётся ошибка, не записывается ни одного байта. Редактор показывает сообщения на языке интерфейса (ниже — по-русски); командная строка выводит их по-французски.

| Сообщение | Обычная причина |
|---|---|
| `синтаксическая ошибка` | неизвестная операция, пропущенная скобка |
| `неизвестная инструкция, директива или макрос` | опечатка; инструкция 65C02 без `.setcpu`; метка без двоеточия |
| `режим адресации невозможен для этой инструкции` | `sta #5`, `ldx ($06),y`… |
| `неопределённый символ` | `jsr ECO` вместо `ECHO`; забытый `.include` |
| `символ уже определён` | две метки с одним именем |
| `значение вне допустимого диапазона` | `lda #300`, адрес за `$FFFF` |
| `переход слишком далеко (от -128 до +127 байт)` | замените `bne far` на `beq :+` / `jmp far` / `:` |
| `файл .include не найден` | имя или папка: добавьте `-I` |
| `неправильно закрытый блок (.macro/.endmacro, .if/.endif)` | забытый `.endif` или `.endmacro` |
| `деление на ноль` | в выражении |
| `строка или символ без закрывающей кавычки` | `"HELLO` |
| `значение здесь ещё неизвестно (.org, .res, .if, .repeat)` | этим директивам нужно уже определённое значение |

## Совместимость с ca65 и xa

Встроенный ассемблер следует синтаксису **ca65** (пакет cc65) во всём, что нужно программе из одного блока. Восемь примеров главы 23 были ассемблированы обоими инструментами и сравнены байт в байт:

| Исходник | Байты | Встроенный = ca65 |
|---|---|---|
| `hello.s` | 33 | <span class="status-ok">идентично</span> |
| `clavier.s` | 32 | <span class="status-ok">идентично</span> |
| `hexa.s` | 64 | <span class="status-ok">идентично</span> |
| `decimal.s` | 117 | <span class="status-ok">идентично</span> |
| `jeu.s` | 222 | <span class="status-ok">идентично</span> |
| `macros.s` | 135 | <span class="status-ok">идентично</span> |
| `gen2-lores.s` | 110 | <span class="status-ok">идентично</span> |
| `gen2-hires.s` | 94 | <span class="status-ok">идентично</span> |

Исходники, написанные для **xa** (xa65), распознаются по строкам `#include` или `#define` и переводятся построчно до ассемблирования (номера строк в ошибках остаются верными): `#define`, `#include`, `*=`, `.BYT`, `.ASC`, комментарии `/* */` и метки в столбце 0 без двоеточия. Так ассемблируется слайд-шоу Дэйва Шменка (глава 9) — в те же 3456 байт, что и у xa 2.4.1.

Для **проектов GitHub** библиотека предпочитает ca65 и ld65, если они установлены (или если проект поставляет конфигурацию ld65), по умолчанию с `-D APPLE1`; иначе она использует встроенный ассемблер. Файл `apple1.toml` репозитория задаёт адреса и символы (глава 4).
