# Карта памяти {: .appendix }

![Память Apple-1 в эмуляторе, от векторов монитора до нулевой страницы.](diagrams/ru/memoire.svg "diagram large")

| Адреса | Содержимое | Подробности |
|---|---|---|
| `$0000-$00FF` | нулевая страница | Woz Monitor `$24-$2B`; Integer BASIC `$4A-$FF` (указатели LOMEM `$4A`, HIMEM `$4C`, PP `$CA`, PV `$CC`) |
| `$0100-$01FF` | стек 6502 | |
| `$0200-$027F` | буфер строки монитора | 128 символов |
| `$0280-$0FFF` | базовое ОЗУ (4 КБ) | программы на машинном языке; BASIC между LOMEM (`$0800`) и HIMEM (`$1000`) |
| `$1000-$BFFF` | ОЗУ расширения | по умолчанию в эмуляторе 8 КБ (до `$1FFF`), до 48 КБ с `--ram` |
| `$C000-$C0FF` | ACI: переключение выхода, вход кассеты | любое обращение переключает выход |
| `$C100-$C1FF` | ACI: ППЗУ (программа ACI) | запускается через `C100R` |
| `$4000-$7FFF` | CodeTank карты P-LAB | EPROM 16 КБ, только чтение, когда ПЗУ подключено (поверх ОЗУ) |
| `$C250-$C257` | карта GEN2: переключатели | чтение; страницы текста/LORES `$0400`, `$0800`, HIRES `$2000`, `$4000` |
| `$CC00-$CC01` | карта P-LAB: TMS9918A | `$CC00` данные, `$CC01` управление и состояние; повторяется на `$CC00-$CFFF` |
| `$D010-$D013` | PIA: `KBD`, `KBDCR`, `DSP`, `DSPCR` | глава 22 |
| `$E000-$EFFF` | BASIC | RDK G2 Basic (7 933 байта, нужно ОЗУ до `$FEFF`) или Integer BASIC от Apple (4 КБ ОЗУ, загружается с кассеты или из образа) |
| `$FF00-$FFFF` | Woz Monitor | векторы: NMI `$0F00`, RESET `$FF00`, IRQ/BRK `$0000` |

# Команды Woz Monitor {: .appendix }

Монитор ждёт строку, завершённую <kbd>RETURN</kbd>. Адреса и байты записываются в шестнадцатеричном виде, без `$`; строка может содержать несколько команд через пробел.

| Команда | Действие | Пример |
|---|---|---|
| `адр` | выводит байт по этому адресу | `FFEF` |
| `адр.адр` | выводит диапазон, по 8 байт в строке | `FF00.FF1F` |
| `.адр` | продолжает вывод до этого адреса | `.FF3F` |
| `адр: байт байт …` | записывает байты начиная с адреса | `300: A9 C1 20 EF FF` |
| `: байт …` | продолжает запись | `: 4C 1F FF` |
| `адрR` | запускает программу по этому адресу (`JMP`) | `300R` |
| <kbd>Esc</kbd> | отменяет строку (выводит `\`) | |
| `_` (backspace) | отменяет последний символ | |

{{!адрR}}{{!адр.адр}}

Строка длиннее 127 символов отменяется, как по Esc. После `R` монитор сначала выводит байт по адресу (`0300: A2`), затем управление берёт программа.

| Адрес | Команда | Роль |
|---|---|---|
| `E000R` | холодный запуск BASIC | стирает программу |
| `E2B3R` | тёплый запуск BASIC | сохраняет программу |
| `C100R` | программа ACI | затем `начало.конецR` (чтение) или `начало.конецW` (запись) |
| `FF00R` | программный RESET монитора | |

# Временные параметры ACI {: .appendix }

Длительности создаёт программа ACI, отсчитывая такты между двумя переключениями выхода. Значения измерены в эмуляторе, который выполняет эту программу на своём 6502 (тактовая частота 1,022727 МГц, с задержкой в 4 такта каждые 65 тактов на регенерацию памяти):

| Элемент | Такты | Длительность | Частота |
|---|---|---|---|
| полупериод заголовка | 592 | 618 мкс | ≈ 809 Гц |
| первая половина стартового бита | 180 | 188 мкс | |
| полупериод «0» | 238 | 248 мкс | ≈ 2,0 кГц |
| полупериод «1» | 473 | 494 мкс | ≈ 1,0 кГц |
| полный заголовок | 16 390 полупериодов | ≈ 10,1 с | |

Формат записи:

<ol class="steps">
<li><strong>заголовок</strong>: около 10 секунд полупериодов по 618 мкс;</li>
<li><strong>стартовый бит</strong>: один короткий полупериод (188 мкс), затем полупериод «0»;</li>
<li><strong>данные</strong>: каждый байт старшим битом вперёд, один полный период на бит;</li>
<li>больше ничего: ни длины, ни адреса, ни контрольной суммы. Диапазон задаёт команда чтения.</li>
</ol>

При чтении программа ACI измеряет полупериоды циклом в 12 тактов. Стартовым битом она считает любой полупериод короче 31 итерации (≈ 372 такта, 388 мкс), а «0» от «1» отделяет примерно на 0,74 мс полного периода. Декодер файлов эмулятора принимает заголовки от 0,40 до 0,90 мс на полупериод, что покрывает инструмент c2t (1 кГц) и колебания скорости ленты.

# Набор символов 2513 {: .appendix }

![64 символа Signetics 2513 так, как их рисует эмулятор: коды от $20 до $5F (с битом 7 — от $A0 до $DF).](img/charset-2513.png "large")

Генератор символов знает только 64 знака: пробел, знаки препинания, цифры и заглавные латинские буквы. Терминал сохраняет только 6 бит полученного кода:

| Посланный код | Отображение |
|---|---|
| `$20-$5F` (или `$A0-$DF`) | символ из таблицы |
| `$60-$7F` (строчные, или `$E0-$FF`) | соответствующая заглавная буква (`$40-$5F`) |
| `$0D` (или `$8D`) | новая строка |
| прочие `$00-$1F` | ничего: игнорируются |

Каждый символ — матрица 5 × 7 точек в ячейке 7 × 8; экран — 40 × 24 символа, то есть 280 × 192 точки.

# Ловушки и особенности поведения {: .appendix }

Мелочи, которые удивляют в первый раз. Ни одна из них не ошибка; у каждой есть причина.

- **BASIC и RUN.** **▶ Запустить** в редакторе запускает BASIC, загружает листинг и набирает за вас `RUN`. Программа, запрашивающая ввод, ждёт ваших клавиш на экране Apple-1: сначала щёлкните по экрану.
- **RND.** Первый `RND` запуска всегда был бы одним и тем же на только что сброшенной машине; **▶ Запустить** ждёт случайное время перед `RUN`, чтобы игра не начиналась всегда одинаково.
- **Команды кассеты.** Строка «Кассета, на настоящем Apple-1» под редактором — это команда Woz Monitor, которую нужно набрать на настоящей машине (`C100R`, затем команды `R` для диапазонов) перед воспроизведением ленты. Это подсказка, а не то, что нужно набирать в эмуляторе.
- **Клавиатура идёт только в одно место.** Строка внизу окна говорит, куда: в Apple-1, в редактор, в поле. Щелчок по экрану Apple-1 направляет клавиши в машину; щелчок в редакторе возвращает их. После щелчка по ошибке в списке редактора клавиши возвращаются в редактор.
- **Отладчик на паузе.** Клавиши, набранные, пока машина на паузе, не теряются, но сохраняется только **последняя** (защёлка настоящей клавиатуры хранит один символ); она передаётся, когда вы продолжаете.
- **Точки останова привязаны к программе.** Загрузка другой программы (файл, библиотека, ассемблер) стирает точки останова и метки предыдущей. Ваши точки останова сохраняются от сеанса к сеансу, только пока вы не загрузили что-то другое.
- **Вставка средней кнопкой.** В редакторе щелчок средней кнопкой переносит туда курсор и вставляет **первичное выделение** X11/Wayland (текст, который вы только что выделили в любом приложении). Редактор пока не *записывает* своё выделение в первичное: чтобы скопировать из редактора, используйте <kbd>Ctrl</kbd>+<kbd>C</kbd>.
- **Маленькие окна.** На мониторе шириной меньше 1400 пикселей расположение первого запуска — редактор и экран; в меню **⊞ Расположение ▾** можно выбрать другое. На экране 1024 × 768 панель инструментов прокручивается по горизонтали: кнопка **»** открывает группу «Кассета», вместо того чтобы обрезать её справа. Фиксированный масштаб (<kbd>Ctrl</kbd>+<kbd>+</kbd>) больше панели экрана сохраняется, и экран прокручивается в своей панели; строка состояния сообщает об этом.
- **Сохранение безымянной вкладки.** **Сохранить как** (значок, <kbd>Ctrl</kbd>+<kbd>S</kbd> или меню правого щелчка по вкладке) никогда не оставляет две вкладки для одного файла: уже открытая вкладка этого файла закрывается.
- **Первый запуск и сеть.** При первом запуске программа обращается к GitHub за демонстрационным проектом (глава 4); удалите проект из списка «Проекты GitHub» в **⚙ Настройки**, чтобы прекратить это навсегда.
- **Чтение клавиатуры в G2 Basic.** Клавиша, нажатая во время работы программы, останавливает её, как в оригинале, а `INPUT` ждёт. Игра, которой нужно следить за клавишами, вызывает `KEY(0)` в главном цикле (глава 15); после этого клавиша программу больше не останавливает.
- **Метки и точки останова.** Точка останова на метке, которой ещё нет (набранная до ассемблирования или запуска), сохраняется и ставится, когда метка появляется.
- **Расположения и окна.** Сохранённое расположение помнит закреплённые панели, открепённые окна (место и размер) и размер главного окна. Оно не помнит, какое окно владеет клавиатурой.
